# Question 5

A new deployment called `alpha-mysql` has been deployed in the `alpha` namespace. However, the pods are not running. Troubleshoot and fix the issue. The deployment should make use of the persistent volume `alpha-pv` to be mounted at `/var/lib/mysql` and should use the environment variable `MYSQL_ALLOW_EMPTY_PASSWORD=1` to make use of an empty root password.

Important: Do not alter the persistent volume.

Troubleshoot and fix the issues

## Documentation
- Search for "pvc" or "pv" / "persistentvolumes"
- https://kubernetes.io/docs/concepts/storage/persistent-volumes/
- I search for "reserving persistent volume" https://kubernetes.io/docs/concepts/storage/persistent-volumes/#reserving-a-persistentvolume and edit the pvc yaml from there.
- Note that I have to edit the existing PV's `storageClassName` to empty string in order for the pv/pvc to bound.. might also need to set `claimRef` to confirm the binding although i did not test that.. 

## Solution

Use the command kubectl describe and try to fix the issue.

Solution manifest file to create a pvc called mysql-alpha-pvc as follows:

```yaml
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: mysql-alpha-pvc
  namespace: alpha
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
  storageClassName: slow
```
