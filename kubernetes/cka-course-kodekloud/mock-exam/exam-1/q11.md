# Mock Exam 1 - Question 11

## Task

Create a Kubernetes **Gateway** resource with the following specifications:

- **Name**: `web-gateway`
- **Namespace**: `nginx-gateway`
- **Gateway Class Name**: `nginx`
- **Listeners**:
  - **Protocol**: `HTTP`
  - **Port**: `80`
  - **Name**: `http`

## Topics Tested

- **Gateway API**: Understanding the next-generation Kubernetes ingress
- **Gateway Resource**: Creating Gateway objects with listeners
- **GatewayClass**: Referencing the correct gateway controller class
- **Namespace Management**: Creating resources in specific namespaces

### Official Documentation

- [Gateway API](https://gateway-api.sigs.k8s.io/)
- [Gateway Resource](https://gateway-api.sigs.k8s.io/api-types/gateway/)
- [GatewayClass](https://gateway-api.sigs.k8s.io/api-types/gatewayclass/)

## Sample Solution

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: web-gateway
  namespace: nginx-gateway
spec:
  gatewayClassName: nginx
  listeners:
    - name: http
      protocol: HTTP
      port: 80
```

### Apply the configuration

```bash
# Create namespace if it doesn't exist
kubectl create namespace nginx-gateway --dry-run=client -o yaml | kubectl apply -f -

# Apply the Gateway
kubectl apply -f web-gateway.yaml
```

## Verification

```bash
# Check Gateway
kubectl get gateway web-gateway -n nginx-gateway

# Describe for details
kubectl describe gateway web-gateway -n nginx-gateway

# Check Gateway status
kubectl get gateway web-gateway -n nginx-gateway -o yaml
```

## Key Concepts

- **Gateway API** = Next-generation Kubernetes Ingress
- **Gateway** = Defines how traffic enters the cluster
- **GatewayClass** = Defines the controller (e.g., nginx, istio)
- **HTTPRoute** = Routes traffic from Gateway to Services (not in this task)
